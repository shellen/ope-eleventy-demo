Open Portable Entitlement · AT Protocol

Subscriber-only posts on atproto, with OPE deciding who reads

atproto spaces let a publisher keep posts that only some accounts can read. A space can hand each "may this person read?" decision to an outside service. Pointed at an OPE License Server, that question becomes "do they have an active subscription?", the same subscription that unlocks the publisher's site and every OPE app.

● atproto spaces are in alpha. The whole path, from signing in to reading posts, passes against Bluesky's own spaces PDS run locally. It hasn't run against a hosted space yet.

How a subscriber reads

  1. Subscribe once OPE

    At the publisher's License Server, from the blog or from any OPE app. It's the same subscription the rest of the demo uses.

  2. Link an atproto account OPE

    On the License Server's account page, the subscriber signs in with their Bluesky (or other atproto) account. The License Server asks only for their identity: it learns the account's DID, and can't post or read as them.

  3. Open the space in an atproto app atproto

    The app gets a short-lived delegation token from the subscriber's own server, then asks the space's host for a space credential.

  4. The space asks the License Server atproto OPE

    The space's policy is managedspace, with the License Server as its managing app. The host calls checkAccess for this subscriber's DID, signed with the publisher's key.

  5. The License Server answers from the subscription OPE

    {"read": true, "write": false} while the subscription is active. Subscribers read; only the publisher writes.

  6. The app reads the posts atproto

    With a space credential valid for 10 minutes (60 at most), bound to the app's key: each request is signed with that key. When the subscription ends, the License Server answers no to the next request for a credential. Only the publisher's server can cancel a credential early, so one already issued lasts until it expires, within the hour OPE allows.

Working now

  • The whole path, tested against Bluesky's own spaces-alpha PDS run locally: the subscriber signs in on the PDS's own page to link their account, the publisher writes posts into the space, the PDS asks the License Server, and an app reads the posts with the credential it gets. Unsubscribed, cancelled, and unlinked readers are refused.
  • Account linking by signing in (atproto OAuth, identity only). The License Server checks that the server vouching for the account is the one its own PDS names. Works on the live demo with a real Bluesky account.
  • The License Server's managing-app endpoint, which checks that each request is signed by the space's owner, and its did:web identity.
  • Answers from the same subscriptions the blog and the reader app use.
  • Runs on Cloudflare Workers with the rest of the License Server.

Not yet

  • A hosted space. The spaces alpha server is invite-only, and the launch is expected within weeks.
  • Live access. The live License Server doesn't manage any space until it's configured with one, and there's no hosted space to configure yet.
  • A reader app for spaces. The test plays the app. The demo's reader app doesn't open atproto spaces.
  • Early cancellation. Only the publisher's server can cancel a credential before it expires; the License Server can't ask it to yet.
  • Per-user checks inside apps. A space credential lets an app sync the space, not decide which of its users see it. An app serving many users has to check each one's subscription itself. OPE gives it a way to, but nothing in the demo does it yet.
  • A stable API. Names still change from week to week: on November 12 the call for a credential was renamed, and the access check settled on checkAccess. The License Server answers the old name too.
